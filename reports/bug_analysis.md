# Bug Hunt — анализ найденных ошибок

## Цель

Во втором ноутбуке требовалось найти три семантические ошибки в реализации MiniGPT, объяснить механизм их влияния на вычисления, исправить их и проверить модель повторным прогоном тестов и коротким обучением.

## 1. Ошибка в позиционном кодировании

**Функция:** `sinusoidal_positional_encoding`

**Проблема:** позиции создавались с отсчётом от 1 вместо 0:

```python
torch.arange(1, length + 1)
```

**Почему это ошибка:** синусоидальное позиционное кодирование задаёт вектор для позиции `0`, у которого синусные компоненты равны нулю, а косинусные — единице. Начало отсчёта с единицы сдвигает все позиционные представления и нарушает ожидаемое соответствие позиции и её кодирования.

**Исправление:**

```python
torch.arange(0, length)
```

## 2. Ошибка в LayerNorm

**Функция:** `LayerNorm.forward`

**Проблема:** среднее и дисперсия вычислялись по `dim=0`, то есть по batch axis.

**Почему это ошибка:** LayerNorm должна нормализовать признаки каждого токена независимо. При вычислении статистик по батчу результат для одного примера начинает зависеть от других элементов батча. Это уже не требуемая нормализация по признакам.

**Исправление:**

```python
mean = x.mean(dim=-1, keepdim=True)
var = x.var(dim=-1, keepdim=True, unbiased=False)
```

Последняя ось соответствует размерности признаков токена.

## 3. Ошибка в Scaled Dot-Product Attention

**Функция:** `scaled_dot_product_attention`

**Проблема:** softmax применялся по `dim=-2`, то есть по оси Query, вместо оси Key.

**Почему это ошибка:** для каждого Query веса должны образовывать распределение по всем Key. Поэтому сумма весов по последней оси должна быть равна единице. При нормализации по Query это свойство нарушается, и матрица перестаёт иметь ожидаемую интерпретацию весов внимания.

**Исправление:**

```python
weights = torch.softmax(scores, dim=-1)
```

## 5. Проверка после исправлений

После исправления ошибок повторно выполнен набор открытых тестов. Проверки охватывают позиционное кодирование, независимость LayerNorm от других элементов батча, корректность attention, causal mask, отсутствие утечки будущих токенов, FFN, residual path и генерацию.

## 6. Эксперимент обучения MiniGPT

Для дополнительной проверки модель обучалась на искусственном символьном корпусе:

```python
text = "алгоритм внимания смотрит на все позиции сразу. " * 200
```

Корпус намеренно простой. Эксперимент предназначен для проверки способности модели выучить повторяющийся шаблон, а не для оценки качества большой языковой модели.

### Конфигурация

| Параметр       |     Значение |
| -------------- | -----------: |
| `context_size` |           64 |
| `d_model`      |          128 |
| `n_heads`      |            4 |
| `n_layers`     |            2 |
| `d_ff`         |          512 |
| `dropout`      |          0.1 |
| Optimizer      |        AdamW |
| Learning rate  |       0.0003 |
| Batch size     |           32 |
| Число шагов    |          600 |
| Seed           |           42 |
| Токенизация    | Посимвольная |

Размер словаря вычисляется как количество уникальных символов в строке корпуса. `d_ff` задаётся автоматически как `4 * d_model`.

### Результат

В сохранённом прогоне loss снизился с `3.1566` на первом шаге до `0.0293` после 600 шагов. Сгенерированный текст воспроизводит обучающий шаблон.

Это подтверждает, что исправленная модель способна обучаться на данном искусственном корпусе. Такой результат сам по себе не доказывает качество или обобщающую способность модели на произвольном тексте.

Были выявлены и устранены три ошибки, каждая из которых нарушала математический смысл соответствующей операции Transformer. После исправлений все 17 проверок прошли успешно, а короткий эксперимент показал снижение функции потерь и воспроизведение обучающего шаблона.
