## 1. Разбиение и объединение голов

### `split_heads`

Вход имеет форму:

\[
(B, L, d\_{model})
\]

Сначала последняя размерность разбивается на `n_heads` групп по `d_head = d_model // n_heads`, затем оси переставляются:

```python
x = x.reshape(batch_size, seq_len, n_heads, d_head)
x = x.transpose(1, 2)
```

Результат имеет форму:

\[
(B, n*{heads}, L, d*{head})
\]

Важно не только получить нужную форму, но и сохранить правильное распределение каналов: голова `h` должна получить срез `x[..., h*d_head:(h+1)*d_head]`.

### `merge_heads`

Операция выполняется в обратном порядке:

```python
x = x.transpose(1, 2)
x = x.contiguous()
x = x.reshape(batch_size, seq_len, n_heads * d_head)
```

После `transpose` тензор может быть non-contiguous. Вызов `contiguous()` создаёт представление с непрерывным расположением элементов в памяти перед `reshape`.

## 2. Scaled Dot-Product Attention

Для Query, Key и Value вычисляются оценки совместимости:

\[
S = \frac{QK^\top}{\sqrt{d_k}}
\]

Далее при наличии маски запрещённые позиции заменяются на `-inf`, после чего softmax применяется по последней оси — оси Key:

\[
A = softmax(S + M)
\]

Выход внимания:

\[
O = AV
\]

В реализации:

```python
scores = query @ key.transpose(-2, -1)
scores = scores / math.sqrt(query.size(-1))

if mask is not None:
    scores = scores.masked_fill(mask == 0, float("-inf"))

weights = torch.softmax(scores, dim=-1)

weights_for_values = weights
if dropout is not None:
    weights_for_values = dropout(weights)

out = weights_for_values @ value
return out, weights
```

### Почему функция возвращает два значения

`out` — контекстное представление каждого токена после взвешенного суммирования `Value`. Оно передаётся следующим слоям модели.

`weights` — матрица распределений внимания. Она показывает, какие позиции Key учитываются при обработке каждого Query. Матрицу можно сохранять для последующего анализа и визуализации.

Важная деталь реализации: dropout применяется к копии весов, используемой при умножении на `Value`, а возвращаемые `weights` остаются softmax-распределением до dropout. Поэтому при обучении строки возвращаемой матрицы суммируются к единице.

## 3. Multi-Head Attention

`MultiHeadAttention` выполняет отдельные линейные проекции для Query, Key и Value, разбивает их на головы, применяет causal mask и объединяет результаты:

1. `w_q`, `w_k`, `w_v` формируют Q, K и V.
2. `split_heads` переносит ось голов на позицию перед длиной последовательности.
3. Causal mask запрещает каждой позиции учитывать будущие токены.
4. Scaled Dot-Product Attention вычисляется независимо для каждой головы.
5. `merge_heads` объединяет головы.
6. `w_o` выполняет выходную проекцию.

## 4. TransformerBlock

В ноутбуке реализован блок в схеме pre-norm:

```python
norm_x = self.norm1(x)
attn_out, weights = self.attn(norm_x)
x = x + attn_out

norm_x = self.norm2(x)
ffn_out = self.ffn(norm_x)
x = x + ffn_out

return x, weights
```

В блоке две остаточные связи:

- вход блока складывается с выходом attention;
- результат первой остаточной связи складывается с выходом FFN.

Нормализация выполняется до соответствующего подслоя. Блок возвращает обновлённые представления и веса внимания.

## 6. Наблюдение

Одним из неочевидных моментов в TODO 3 для меня стало то, что функция Scaled Dot-Product Attention должна возвращать два значения результат внимания (out) и матрицу весов внимания (weights). Первое значение содержит контекстные представления токенов, полученные в результате взвешенного суммирования Value, и используется в дальнейших вычислениях Transformer. Второе значение представляет собой распределение весов внимания между токенами и позволяет анализировать, на какие позиции последовательности обращает внимание модель. Изначально я воспринимал матрицу весов только как промежуточный этап вычисления, но оказалось, что её также необходимо сохранять для последующей визуализации и интерпретации работы модели.
